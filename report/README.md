# Реферат и презентация

Актуальная версия по предоставленному автором образцу находится локально в `../Готовая_курсовая/` относительно корня репозитория. Она содержит персональные титульный лист и лист задания, поэтому не публикуется в этом публичном репозитории. Исходный текст `report.md` сохранён. Старые файлы `output/` ниже относятся к предыдущему оформлению.

Для переноса оформления используется `format_like_reference.py`: он копирует реальные компоненты предоставленного DOCX, включая стили, колонтитул, таблицы титула и герб. Названия общих разделов и глав соответствуют новому образцу; текст, ссылки, таблицы, рисунки и листинги остаются из нашей работы. Оглавление сверяется с итоговой пагинацией. Для сборки нужны `lxml` и Pillow; пример без персональных данных:

```sh
python report/format_like_reference.py --reference '../Курсовая.docx' --author 'Фамилия Имя Отчество' --group 'ГРУППА' --pages 34
```

Файл образца не включён в репозиторий и не изменяется при сборке. После изменения текста нужно отрисовать документ, записать соответствие заголовков и номеров страниц в `../Готовая_курсовая/toc-pages.json`, повторить сборку с фактическим числом страниц и проверить все страницы. Старый `build.py` не переносит новое оформление.

После содержательной сверки 06.11.2026 уточнены определения с привязкой к стенду и ссылками, обоснование advisory-блокировки и интерпретация уже проведённых испытаний. Добавлены два первоисточника по частичным индексам PostgreSQL и подам Kubernetes. Актуальная локальная версия содержит 35 страниц и 16 источников; число источников в выходных сведениях вычисляется генератором из библиографии. Титул и задание сохранены. Повторный отчёт внешней проверки оригинальности не получен.

## Предыдущая версия

Реферат содержит 37 страниц, 5 рисунков, 5 таблиц и 14 источников.

В `output/` находятся редактируемый DOCX, PDF реферата, PPTX и PDF презентации из девяти слайдов, а также отдельные титульный лист, лист задания и заявление на тему в DOCX/PDF. Исходный текст — `report.md`, собственные схемы и фактический скриншот — `assets/`, воспроизводимый генератор — `build.py`.

До сдачи необходимо заполнить ФИО, группу, сведения о руководителе, сроки и подписи; согласовать лист задания и титул с актуальным шаблоном кафедры. Эти данные не были предоставлены, поэтому в документах оставлены пустые поля.

Временная методичка явно требует начальный раздел «Аннотация», поэтому это название сохранено; весь документ именуется рефератом. Использованы поля 3/1,5/2/2 см, Times New Roman 14, интервал 1,5 и отступ 1,25 см; для таблиц/листингов применены меньший кегль и одинарный интервал. Нумерация учитывает титул/задание без печати номеров на этих листах.

Источники — официальные технические документы и сайты аналогов. Требование отзыва из примера об источниках из ЭБС необходимо уточнить. Найдена подходящая библиографическая запись: Иванова И. А., Котилевец И. Д., Хаханов И. С. «Основы построения контейнерной архитектуры современных приложений». РТУ МИРЭА, 2022, 117 с.; Лань: https://e.lanbook.com/book/240035. Полный текст в этой работе не был доступен, поэтому источник не включён как изученный. При подтверждении обязательности ЭБС автору нужно получить и изучить материалы через вузовский доступ и дополнить ссылки. Не следует указывать непрочитанный источник как прочитанный.

Проверка оригинальности выполняется автором в требуемой вузом системе. Готового отчёта антиплагиата и обещанного процента нет. Содержание основано на собственном коде, схемах и реальных испытаниях; результаты облачного запуска не выдуманы.

## Пересборка
```sh
python -m pip install -r report/requirements.txt
python report/build.py
```
Для экспорта PDF используйте LibreOffice либо Word/PowerPoint. После изменений текста обновите оглавление/номера страниц и проверьте PDF визуально. `pages.json` фиксирует номера текущей проверенной вёрстки, не является динамическим полем Word.

## Текущая редакция 08.11.2026

В локальной персональной версии 39 страниц, семь схем и скриншот (восемь рисунков), пять таблиц, 22 источника и одно приложение. Сценарий демонстрации удалён. Оформление, титул и задание сохранены; оглавление сверено с окончательным PDF. Сведения предыдущих дат выше описывают историю, а не текущий объём.

Схемы строятся отдельно, без пересоздания документа старым генератором:

```sh
python report/draw_diagrams.py
python report/format_like_reference.py --reference '../Курсовая.docx' --author 'Фамилия Имя Отчество' --group 'ГРУППА' --pages 39
```

Для отрисовки используется Arial (macOS) либо DejaVu Sans (Linux). PNG содержат достаточно пикселей для печати; SVG сохраняют редактируемые объекты. После изменения текста повторяют отрисовку, сверку оглавления и сборку. `build.py` также использует новый модуль схем, но по-прежнему создаёт прежнее оформление документа и не заменяет `format_like_reference.py`. Проверка добавленных библиотечных и научных источников, включая границы доступа к текстам, описана в [source-verification.md](source-verification.md).

После стилистического просмотра от 08.11.2026 переработаны 49 фрагментов: повторные оговорки заменены прямыми описаниями реализации и результатов. Технические ограничения сохранены. Итог — 39 страниц; оформление и состав иллюстраций и источников прежние. Оценка внешнего детектора после редактуры не получена.


## Актуальная презентация

08.11.2026 обновлены девять слайдов: возможности приложения, дорожная модель, состав компонентов, назначения, варианты запуска, CI/CD и результаты. На слайдах используются новые схемы из `assets/`. Заметки докладчика содержат пояснения и ссылки на результаты.

Версия для защиты с ФИО, группой и руководителем хранится рядом с курсовой, вне репозитория: `../Готовая_курсовая/Презентация_Тактика.pptx` и `.pdf` относительно корня проекта. Публичная копия без персональных данных обновлена в `report/output/Презентация_Тактика.pptx` и `.pdf`.

Редактор `update_slides.mjs` импортирует существующую презентацию и обновляет её текст, изображения и заметки. Нужен `@oai/artifact-tool` из среды подготовки документов; переменная `RUNTIME_NODE_MODULES` указывает каталог пакетов этой среды. Пример сборки черновика:

```sh
node report/update_slides.mjs --output /tmp/taxi-slides/draft.pptx
```

Для персональной копии доступны аргументы `--author`, `--group`, `--supervisor`. Такой файл сохраняют вне публичного репозитория. Перед заменой файлов в `output/` проверяют структуру PPTX, границы объектов, отрисовывают все слайды и экспортируют соответствующий PDF. Устаревший `build.py` больше не пересоздаёт презентацию.


## Оформление по дополнительному образцу от 10.11.2026

Актуальные персональные DOCX и PDF в `../Готовая_курсовая/` содержат 38 страниц, восемь рисунков, пять таблиц, 22 источника и одно приложение. Дополнительный образец начинается с реферата и не содержит титула: ранее согласованные титул и задание сохранены. Из нового образца перенесены параметры абзацев, заголовков, оглавления, подписей, библиографии, таблиц и предварительных страниц без печатных номеров. Содержание нашей работы сохранено; ширины собственных таблиц адаптированы к количеству колонок.

`match_body_reference.py` применяет это оформление к уже собранному документу. Он импортирует стили под отдельными идентификаторами, сохраняет определения стилей титула и проверяет неизменность титульных элементов и изображений. Исходный образец указывается локальным путём и не публикуется. Пример второго этапа сборки:

```sh
python report/match_body_reference.py \
  --reference '/path/to/body-reference.docx' \
  --input '/path/to/approved-report.docx' \
  --output '../Готовая_курсовая/Курсовая_такси.docx' \
  --pages 38 \
  --page-map '../Готовая_курсовая/toc-pages.json'
```

После изменения текста необходимо заново отрисовать документ, определить фактическую пагинацию, обновить `--pages` и JSON с номерами заголовков, повторить второй этап и проверить DOCX/PDF. Параметр `--input` удобно направлять на резервную копию предыдущей оформленной версии. Генератор не запускает Word/LibreOffice и сам не рассчитывает номера страниц. Файлы DOCX/PDF в корне репозитория исключены из Git, чтобы случайно не опубликовать предоставленные образцы.
