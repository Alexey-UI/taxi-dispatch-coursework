# Расширенная карта и движение по улицам

## Общая модель
Город имеет размеры 200×140 единиц вместо прежних 100×100. Вертикальные улицы находятся на X = 5,15,…,195, горизонтальные — Y = 5,15,…,135. Все пересечения связаны, улицы двусторонние, препятствий и односторонних участков пока нет. Это автономный учебный граф, а не карта реального города.

Единственный источник конфигурации — `internal/city.json`. Go встраивает его в бинарник и возвращает объект city в `/api/state`. Браузер и Node.js используют эту конфигурацию и общий модуль `web/roads.mjs`. Контрольные расстояния из `internal/road-fixtures.json` проверяются и Go, и JavaScript.

## Построение пути
Точка привязывается к ближайшей вертикальной либо горизонтальной улице. На пересечении уже доступны обе оси; внутри сегмента нужно сначала достичь одного из двух соседних перекрёстков. Для каждой пары входного и выходного перекрёстка складываются длина подхода, манхэттенское расстояние между узлами и длина конечного участка. Выбирается минимальный вариант. Для общей улицы возможен прямой путь вдоль неё.

Обычное |dx|+|dy| между произвольными точками тоже бывает неверным. Пример: (12,15) → (13,25). Обе точки находятся на параллельных улицах между X=5 и X=15. Нужно пройти через поперечную улицу; кратчайший путь равен 15, а не 11. На регулярной сетке перебора соседних перекрёстков достаточно; Dijkstra понадобился бы при произвольных рёбрах, перекрытиях и весах.

Dispatcher выбирает ближайшего по этой дорожной длине. Например, относительно подачи (12,15) водитель (13,25) ближе по прямой, но автомобиль (25,15) ближе по дорогам. Тест Go проверяет это различие.

## Время и анимация
Скорость по умолчанию — 1,2 единицы в секунду. Simulator использует фактическое прошедшее время между тиками, ограничивая большой скачок после задержки двумя секундами. Пауза не накапливает движение. Сгенерированные поездки имеют длину не менее 45 единиц: движение занимает минимум 37,5 секунды без учёта подачи; многие маршруты длятся около минуты–двух и более.

При переходе через поворот остаток бюджета шага переносится на следующий участок. Поэтому машина не телепортируется на перекрёсток и не теряет часть пути. Браузер тоже интерполирует вдоль полилинии через requestAnimationFrame: обычный CSS-переход между двумя координатами мог бы срезать угол квартала.

На карте доступны увеличение/уменьшение, возврат к общему виду, перетаскивание и полноэкранный режим. Выбор подачи/назначения учитывает текущие масштаб и смещение; точки привязываются к дороге. Жёлтый пунктир показывает путь к пассажиру, зелёный — поездку; точка показывает текущую цель.

## Совместимость данных
Новый файл миграции `002_road_city.sql` переносит прежние координаты на ближайшие улицы. Заказы не удаляются. `schema_migrations` исключает повторное применение; вся операция защищена транзакционной advisory-блокировкой. Перед локальным обновлением создан backup `artifacts/backups/pre-roads.dump`. Число существующих заказов до и после миграции — 35, водителей вне дорог — 0.

## Проверки
- Go: проекция, границы, расстояния, случай отличия ближайшего по дороге от ближайшего по прямой.
- Node.js: 300 маршрутов с выборкой промежуточных точек, отсутствие диагональных сегментов, сохранение бюджета на повороте, 1000 воспроизводимых заказов, минимальная длительность.
- Интеграция: отдельный чистый Compose на 8092, два dispatcher, 63 HTTP-проверки.
- Браузер: 120 кадров фактических маркеров — все центры на улицах, положение меняется; масштабирование и мобильная вёрстка работают.
