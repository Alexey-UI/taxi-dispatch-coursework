# Taxi Dispatch — курсовая работа по НиАСПО

Учебная система автоматической обработки и распределения заказов такси. Аудитория: автор, преподаватель, публичные наблюдатели и гости. Приоритеты: корректность распределения, контейнеризация, Kubernetes, CI/CD, понятное обучение. Бизнес-функции минимальны.

## Правила
1. Перед нетривиальной задачей проверить доступную межсессионную память и docs/validation.md. Источники требований — DOCX и ZIP в родительской папке, договорённости в docs/requirements.md. Исходные материалы не изменять.
2. Go: API и dispatcher. JavaScript: интерфейс и Node.js-симулятор. PostgreSQL — источник истины; Redis — ускоряющие уведомления. Не добавлять Kafka или мониторинговые платформы без необходимости.
3. Облако, DNS и платные ресурсы пока не изменять. GitHub-репозиторий и коммиты разрешены. Репозиторий публичный по явному указанию автора; уроки ../courses/ не публиковать.
4. После этапов обновлять ../courses/: объяснения, теория, примеры, упражнения и разбор реализации. Реферат писать после проверки проекта, по реальным результатам. Не выдумывать тесты, облачный деплой или отчёт антиплагиата.
5. Не публиковать секреты, реальные персональные данные и необработанные служебные логи. Публичная лента содержит только события демонстрации.

## Структура
- cmd/taxi, internal — Go-приложение и SQL-схема.
- web — JavaScript-интерфейс, автономная карта и стили.
- simulator — Node.js-симулятор и его тесты.
- deploy — Docker, Helm, k3d и Terraform-заготовка.
- artifacts — игнорируемые временные скриншоты и резервные копии.
- scripts — проверка, резервное копирование, локальный запуск.
- docs — требования, архитектура, эксплуатация, подтверждения проверок.
- ../courses — учебные материалы на русском, вне репозитория.
- report — пояснительная записка, презентация и генератор документов.
- .github/workflows — CI/CD.

## Проверка изменений
Go: gofmt, go vet ./..., go test -race ./...; Node: node --test simulator/*.test.mjs; инфраструктура: docker compose config, helm lint и helm template. Интеграция: scripts/smoke.mjs против работающего Compose.

## Не делать
- Не заявлять отказоустойчивость PostgreSQL или ВМ: БД одиночная, локальные узлы k3d работают на одном хосте.
- Не изменять уже применённые миграции; добавлять новые.
- Не считать сборку и push полноценным CD: проверять развёрнутое приложение.
